Click any frame to break it apart. LL counts the data bytes, so the frame is LL+4 on the wire. DS splits into node and subsystem. CC CC is the command, and the payload bytes are numbered the way the decoder profiles refer to them.

What the DS byte means

The DS byte carries two nibbles: the high one addresses a node, the low one selects a subsystem inside it. A high nibble of 0 is a broadcast. The acknowledgement that follows a frame repeats the answering node in its own high nibble, which is why the log can name who replied.

Publishes decoded readings to a broker, so the appliance reaches Home Assistant and anything else that listens. Readings are retained: whoever connects next sees the current state instead of waiting for the machine to change its mind — which on an idle appliance can take hours.

HTTP API

Everything this page does, it does through these endpoints — so anything here can be scripted. Responses are JSON unless stated otherwise, and requests that carry a body expect Content-Type: application/json.

Status

GET/api/v1/info

Device name, uptime, free heap, the bus counters behind the Home page, network state and channel, the chip and bus pins this firmware is running on, the clock, and whether MQTT and password protection are on.

GET/api/v1/health

Post-mortem and pressure: why the device last booted, whether it crashed, the lowest the heap has been, per-task stack headroom, and the size of any stored core dump.

Bus

GET/api/v1/frames

Recent frames and acknowledgements from the device's ring buffer, oldest first. Each item is exactly what the monitor receives live, sequence number and all.

?since=N
only what is newer than sequence N; omit or −1 for everything held
→ latest
newest sequence in the ring, to pass back as since
→ gap
true when the ring no longer reaches back to since + 1
WS/api/v1/ws

The live monitor. Send {"since":N} after connecting and the missed messages are replayed from the ring before the live stream resumes; send −1 for everything held. Messages are {"t":"f"} for a frame, {"t":"a"} for an acknowledgement, plus drop, gap and ota notices.

Appliance and profiles

GET/api/v1/appliance

Which profile is active, what it describes, and whether the appliance is currently heard from.

POST/api/v1/appliance

Activate a profile by id. An empty id forgets the choice and goes back to listening.

{"id": "…"}
a catalogue id, or custom:<slug>
GET/api/v1/readings

The decoded values as they stand, each with its name, unit and whether it is currently available. estimated marks a value the engine carried forward between two readings rather than one the appliance gave.

GET/api/v1/layout

Which entities read which frame, grouped by target and command — what the monitor uses to explain a frame and to fold away the ones a profile marks hidden.

GET/api/v1/profiles

The catalogue carried in the firmware.

GET/api/v1/candidates

Profiles ranked by how much of the observed traffic they explain — the guess the setup page offers, without asking the appliance anything.

GET/api/v1/custom

Your own stored profiles. With an id, the one profile; with download=1, as a file.

?id=custom:slug
a single profile instead of the list
?download=1
send it as an attachment
PUT/api/v1/custom

Store a profile. The body is the profile JSON; the device parses and validates it and refuses anything it cannot read.

?id=custom:slug
required — the slug is the file name and cannot be changed later
?activate=1
also make it the active profile
DELETE/api/v1/custom?id=custom:slug

Remove a stored profile.

GET/api/v1/profile/source?id=…

The JSON a profile is made of, built-in ones included — the starting point when copying one to edit.

GET/api/v1/storage

How much room the stored profiles leave.

Configuration

POST/api/v1/config/wifi

Join a network. The device answers first and then restarts, so the reply arrives on the connection you asked from and the credentials take effect on the way up.

{"ssid", "password"}
an empty password joins an open network
POST/api/v1/config/device

Rename the device. Takes effect on the next restart, and does not change the MQTT identity, which is derived from the MAC.

{"name"}
empty restores the default name
POST/api/v1/config/auth

Set or clear the interface password. Stored as a PBKDF2 digest with a fresh salt, never as the password itself.

{"user", "password", "enabled"}
an empty password clears the credential and forces protection off
GET/api/v1/config/mqtt

The broker settings and whether the client is connected. The password is never sent back — has_password says only that one is stored.

Firmware and diagnostics

POST/api/v1/ota

Upload firmware. The body is the raw image, not a form, and the device reboots into it once it verifies. It confirms the new image only after the network is back — if it cannot be reached, the bootloader falls back to the previous one.

Content-Type
application/octet-stream
GET/api/v1/ota/status

Which slot is running, its version and build date, and whether it is still on probation.

POST/api/v1/restart

Reboot.

POST/api/v1/reset

Erase every setting and reboot as if freshly flashed. Stored profiles live in their own partition and survive this.

GET/api/v1/coredump

The stored crash dump, as a binary attachment, when there is one.

DELETE/api/v1/coredump

Discard it.
